# Evidence-First 管理员评审工作台设计

## 1. 目标

把管理员端从“会话字段查看页”收敛为一个简洁、清晰、证据优先的评审工作台。它服务于本项目的核心命题：验证 AI 是否能够在不替参与者下诊断结论的前提下，依据 20 道半结构化回答完成题内评分、整场证据整合、主动求证和可审计的专家交接。

管理员端不追求展示最多信息，而追求让管理员快速回答三个问题：

1. 这场评估已经形成了哪些可靠证据？
2. 哪些地方仍然没有听清，或存在跨题支持/冲突？
3. 下一步应该优先复核哪里？

## 2. 非目标与硬边界

- 不改变参与者答题、小猫陪伴、安全流程和单题 Rubric 评分逻辑。
- 跨题信息只能用于评估编排和管理员阅读，不得改写任何单题 0/1/2 分数。
- 研究规则分层不是临床诊断、风险预测或自动干预决定。
- 不把总分作为管理员首屏的唯一或最大视觉焦点。
- 不默认展开全部原话、AI 日志和证据细节；信息按层级渐进展开。
- 不引入 WebSocket、复杂图数据库或额外基础设施；继续使用现有持久化 SQLite 和 API。

## 3. 信息架构

管理员空间分成三层：

### 3.1 评估总览

管理员登录后的默认入口。只展示四类最有用的信息：

- 最近更新的评估会话；
- 待专家复核的会话/节点；
- 进入专业安全流程的会话；
- 当前最值得优先查看的未决节点。

总览提供进入“评估会话”“专家工作台”和“成员与权限”的入口，并提供“以测试者身份开始新会话”。成员管理和研究统计不抢占总览主视觉。

### 3.2 单场评估报告

单场报告围绕一张证据地图、一个 20 题矩阵和一条评估路径展开：

- **证据地图**：每个构念同时显示表现方向和证据确定程度；两者视觉分离。
- **20 题矩阵**：默认一行一题，显示状态、证据充分性、AI 把握度、追问/复核标记；点击后展开完整证据链。
- **评估路径**：以时间线显示“发现缺口 → 暂缓/求证 → 用户补充 → AI 重评 → 确认/人工复核”。

报告还显示会话级 AI 摘要、支持/冲突关系、未决节点和版本信息。总分作为辅助指标出现，研究分层明确标注为研究规则。

### 3.3 专家工作台

专家工作台只处理需要判断的节点，不复制完整会话浏览页面。默认按优先级呈现：

- 原始评分与当前有效评分；
- 原话、证据充分性、AI 置信度；
- 相关题目的支持/冲突信号；
- 专家仲裁分、证据充分性、备注和处理状态。

专家动作产生新的审计记录，原始事件和原始评分始终可回放。

## 4. 单场报告数据契约

新增管理员专用的报告聚合接口，优先复用现有事件和会话决策数据：

```text
GET /api/admin/overview
GET /api/admin/sessions
GET /api/admin/sessions/{session_id}
GET /api/admin/sessions/{session_id}/report
```

`/report` 返回以下稳定结构：

```json
{
  "session_id": "...",
  "overview": {},
  "constructs": [],
  "item_matrix": [],
  "timeline": [],
  "probe_summary": {},
  "uncertainty": {},
  "ai_decisions": [],
  "review_queue": [],
  "versions": {}
}
```

报告由持久化事件重建；可以把最新聚合结果写入会话 metadata 作为缓存，但不能替代事件链。

## 5. 可视化原则

第一版只使用能直接支持判断的视觉表达：

- 构念“表现方向 / 证据质量”双条形图；
- 20 题证据矩阵；
- 未决节点优先级列表；
- 支持/冲突关系摘要；
- 评估路径时间线；
- 评分、证据充分性和 AI 置信度的简洁分布。

暂不做复杂雷达图、关系网络图、大面积红黄绿风险视觉或单一综合指数。

## 6. 无感刷新协议

### 6.1 前端行为

- 首次打开列表或详情时显示加载状态；
- 自动刷新和手动刷新时保留旧内容；
- 请求期间只在标题旁显示“正在同步”；
- 成功后显示“刚刚更新”及更新时间；
- 失败时保留旧内容并显示非阻断提示；
- 保持当前选中的会话和滚动位置；
- 防止同一资源的并发刷新；
- 页面不可见时暂停轮询，重新可见时立即同步；
- 自动刷新默认 30 秒，手动刷新始终可用。

### 6.2 数据行为

- 列表刷新先比较 `updated_at`；
- 仅当选中会话版本变化时重新获取详情报告；
- 详情请求返回后做局部状态替换，不把 `selected` 先置空；
- 新请求失败不得覆盖上一次成功数据。

## 7. 语言和视觉气质

- 所有管理员文案使用清晰、短句、因果明确的中文；
- “风险等级”改为“研究分层”或“安全流程状态”；
- “干预建议”改为“复核与支持建议”；
- 任何 AI 摘要都必须标明其为会话级研究建议，不是诊断结论；
- 保持现有汇文明朝体和安静、留白、低饱和视觉，不新增拥挤卡片。

## 8. 错误处理和安全

- 管理员 API 继续由 `require_admin_access` 保护；
- 报告聚合失败时返回可识别错误，不泄露内部路径或密钥；
- 安全触发的会话在报告中优先显示专业流程状态，隐藏可爱化行动入口；
- 任何报告导出都只读取当前管理员有权访问的持久化数据；
- 原始回答、AI 决策、专家仲裁和查看动作继续写入审计链。

## 9. 验收标准

1. 管理员登录后进入评估总览，而不是参与者答题页。
2. 管理员能从总览进入一场会话，并在一个清晰页面看到证据地图、20 题矩阵和评估路径。
3. 管理员能从任意未决节点进入专家工作台并完成仲裁，且原始记录仍可回放。
4. 用户完成会话后，管理员能看到持久化的单场报告，而不是只有逐题列表。
5. 自动刷新期间旧内容不消失、不白屏、不跳回列表首项。
6. 失败刷新不会清空旧数据；恢复后能显示新的更新时间。
7. 报告中跨题信号不会改变单题原始或有效评分。
8. 前端构建、后端编译和现有后端测试全部通过。
