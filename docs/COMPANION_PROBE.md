# 小猫陪伴式自适应澄清协议

小猫不是第二个评分器，也不是“把风险说得可爱”的包装。它是一次短暂的、可退出的共同确认：系统发现一个语义缺口后，先承认自己还没有听完整，再把几条同等位置的理解放到参与者面前，由参与者决定哪一条更靠近自己的意思。

## 什么时候出现

只有会话编排器选出 `CLARIFY_NOW` 或 `CONFIRM_NOW` 时，才展示 `cat_probe`。`DEFER_CLARIFICATION` 只记录缺口，不打断当前 Seed Probes；`SAFETY_FLOW` 直接切换到专业流程，不显示小猫式探针或 playful 动画。

每个题目最多一次自动探针，每个会话最多三次。探针类型有明确分工：

- `CLARIFICATION`：补足尚未表达的具体信息。
- `DISAMBIGUATION`：在多个可能方向之间请参与者辨认，不替其选择。
- `CONFIRMATION`：对已有但不稳定的题内理解换一种说法求证，允许参与者推翻。

跨题支持/冲突只决定“是否值得现在问”，不进入该题的 0/1/2 评分。

## 文案契约

后端返回的 `cat_probe` 包含四段小猫文案：

1. `cat_reflection`：轻轻复述参与者原话，不夸大、不分析。
2. `cat_tentative_understanding`：说出当前缺口，用“我还不确定”而不是结论。
3. `cat_humility`：明确承认可能听偏，并把解释权还给参与者。
4. `cat_invitation`：邀请继续靠近，允许不完整、暂停或改用自己的话。

`options` 只描述语义方向，不出现分数、风险等级、诊断或“正确答案”。协议始终补齐两个出口：

- `other`：不太像，参与者用自己的话说（必须提供自由文本）。
- `not_ready`：今天先放在这里（记录为 `PROBE_PAUSED`，不作为负向证据，也不触发再次自动追问）。

模型提供的文案和选项会经过服务端白名单、长度和禁用词校验；不合格部分回退到题目专属的中性文案。安全状态下的回答不会生成 `cat_probe`。

## 一次完整闭环

```text
AI/规则发现 target_gap
    ↓
编排器决定 CLARIFY_NOW / CONFIRM_NOW
    ↓
小猫反映 + 暂定理解 + 承认可能听偏 + 平行选项
    ↓
参与者选择 / 自由补充 / 今天先放在这里
    ↓
选项与补充写入审计事件（不覆盖原回答）
    ↓
AI/规则依据同一题 Rubric 重新评分
    ↓
CONFIRMED、再次 HUMAN_REVIEW，或保持未决
```

参与者输入不能把会话降级成“无审计的本地评分”：已有会话时，接口错误会留在当前页面并提示重试；只有尚未建立会话时，前端才使用原有的离线体验。
